# SysADV v0.6.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement publicações oficiais/linha do tempo, gerenciamento configurável de fontes judiciais e gestão segura de usuários sobre a SysADV v0.5.0.

**Architecture:** Preserve the Judicial Data Gateway as the integration facade. Add persisted DataSource configuration/health/secrets, OfficialPublication records correlated to processes, and richer user lifecycle/session controls. Frontend exposes Publicações, Fontes de Dados and Usuários as first-class menus.

**Tech Stack:** Node.js 22, TypeScript, Fastify 5, Prisma 6/PostgreSQL 16, React 19/Vite, Zod, Argon2, Docker Compose.

**Spec:** `docs/tecnica/SysADV_Especificacao_Tecnica_v0.6.0.docx`

## Global Constraints

- Release version is exactly `0.6.0` in API, frontend, update/verification scripts and release notes.
- Preserve existing v0.5.0 data; schema evolution must be compatible with `prisma db push`.
- DataJud remains active; DJEN/PJe/Jurisprudence connectors are configurable and may remain disabled until authorized access exists.
- Never expose source secrets in GET responses, logs, audit records, UI or distributable ZIP.
- RBAC is enforced in the API; frontend visibility is only supplemental.
- Publications and movements remain distinct records even when correlated.
- Disabling/locking a user revokes active sessions.
- The last active administrator cannot be disabled, locked, or stripped of ADMIN.
