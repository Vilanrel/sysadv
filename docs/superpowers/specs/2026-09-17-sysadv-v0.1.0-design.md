# SysADV v0.1.0 - Desenho Técnico

Data: 17/09/2026
Status: Aguardando revisão
Base funcional: Especificação Funcional - Sistema de Auxílio aos Advogados para Cálculos Trabalhistas v1.1

## 1. Objetivo da versão

A versão 0.1.0 do SysADV estabelecerá a fundação segura e auditável da plataforma, cobrindo autenticação, autorização, estrutura principal da aplicação, cadastro e consulta de processos, gestão inicial de documentos, indicadores de origem/status e trilha de auditoria.

Esta versão não executará ainda a automação completa do PJe-Calc nem a extração jurídica completa por IA. Esses componentes serão preparados arquiteturalmente para evolução posterior.

## 2. Princípios do produto

1. Toda informação relevante ao cálculo deve manter sua origem e histórico.
2. Nenhuma automação substitui a validação profissional do advogado ou calculista.
3. Divergências devem ser exibidas e não resolvidas silenciosamente.
4. O sistema deve respeitar segregação por organização, escritório e processo.
5. Dados pessoais e processuais devem ser tratados conforme LGPD, sigilo e permissões da fonte.
6. Integrações externas serão desacopladas da regra de negócio principal.
7. Segurança, auditoria e rastreabilidade serão requisitos de primeira classe.

## 6. Autenticação e segurança

### 6.1 Login
O usuário poderá autenticar-se com e-mail e senha.

Requisitos:
- senha armazenada exclusivamente como hash Argon2id;
- nunca armazenar senha em texto claro;
- política de senha configurável;
- bloqueio temporário após tentativas consecutivas inválidas;
- rate limiting por IP e por identidade;
- registro de tentativas de autenticação;
- mensagens de erro que não permitam enumerar usuários.

### 6.2 Sessões
Será utilizada uma estratégia baseada em:
- Access Token de curta duração;
- Refresh Token rotativo;
- Refresh Token persistido de forma protegida/hashed;
- revogação de sessão no logout;
- revogação de todas as sessões em eventos de segurança.

Quando utilizados cookies:
- HttpOnly;
- Secure em produção;
- SameSite apropriado;
- proteção contra CSRF.

### 6.3 MFA
A arquitetura suportará MFA desde a v0.1.0, ainda que sua obrigatoriedade possa ser configurável por organização.

Método inicial recomendado:
- TOTP por aplicativo autenticador.

### 6.4 Recuperação de senha
- Token criptograficamente seguro;
- uso único;
- expiração curta;
- invalidação após utilização;
- auditoria do evento;
- revogação opcional das sessões existentes após redefinição.

### 6.5 Autorização
Modelo RBAC com permissões explícitas por recurso e ação.

Exemplos:
- process.read
- process.create
- process.update
- document.upload
- document.read
- parameter.validate
- audit.read
- user.manage

A API será a autoridade final de autorização; o frontend apenas refletirá permissões para experiência de uso.

Campos iniciais:
- número do processo;
- reclamante;
- reclamado;
- CPF/CNPJ das partes;
- tribunal;
- TRT;
- Vara do Trabalho;
- município;
- advogado responsável;
- data de ajuizamento;
- data de admissão;
- data de desligamento;
- função;
- salário contratual;
- data-base;
- fase processual;
- data prevista para cálculo;
- observações.

A ausência de informação não impedirá a criação do processo; o campo permanecerá Pendente.

- página;

## 15. Auditoria

Eventos obrigatórios:
- login bem-sucedido;
- login recusado;
- logout;
- recuperação de senha;
- alteração de senha;
- ativação/desativação de MFA;
- inclusão/alteração de usuário;
- criação/alteração de processo;
- upload/remoção lógica de documento;
- alteração manual de campo;
- validação de informação;
- chamadas de integração;
- futura execução do PJe-Calc.

Logs de segurança não poderão armazenar senha, token completo ou segredo.

## 16. Integrações

### Integration Gateway
Interface comum para conectores externos.

Responsabilidades:
- autenticação;
- timeout;
- retry controlado;
- circuit breaker;
- normalização de resposta;
- auditoria;
- observabilidade.

### DataJud
Será implementado como conector opcional e parametrizável. Seu uso produtivo ficará condicionado às autorizações e condições jurídicas definidas no Discovery.

### PJe / TRT
Conectores específicos serão adicionados apenas para endpoints e credenciais oficialmente disponibilizados.

### PJe-Calc
A v0.1.0 criará apenas a abstração de integração. O agente local/conector será implementado em versão posterior após PoC técnica.

## 17. Armazenamento de segredos

Segredos não serão versionados no repositório.

Ambientes locais:
- arquivo .env não versionado.

Produção:
- secret manager/cofre de segredos compatível com a infraestrutura escolhida.

API keys e tokens deverão suportar rotação.

## 18. Proteções da API

- validação estrita de entrada;
- queries parametrizadas/ORM;
- headers de segurança;
- CORS restritivo;
- rate limiting;
- limite de tamanho para uploads;
- validação de tipo de arquivo;
- autenticação obrigatória por padrão;
- autorização por recurso;
- logging estruturado;
- correlation/request ID;
- tratamento padronizado de erros;
- ausência de stack trace em produção.

## 19. Upload seguro

O upload deverá:
- validar MIME type e extensão;
- limitar tamanho;
- gerar hash;
- usar nome interno não controlado pelo usuário;
- impedir path traversal;
- armazenar fora da raiz pública do web server;
- preparar integração futura com antivírus/malware scanning;
- registrar auditoria.

## 23. Critérios de aceite da v0.1.0

1. Usuário autenticado consegue acessar somente funcionalidades permitidas.
2. Usuário não autenticado é redirecionado ao login.
3. Sessão pode ser revogada.
4. Senhas não são armazenadas em texto claro.
5. Tentativas inválidas são controladas e auditadas.
6. Administrador consegue gerenciar usuários.
7. Advogado consegue criar e consultar processo autorizado.
8. Processo suporta os campos definidos na EF.
9. Campos relevantes suportam origem e status.
10. Documentos podem ser vinculados ao processo com hash e metadados.
11. Eventos críticos geram AuditEvent.
12. Dados de organizações diferentes permanecem segregados.
13. API possui documentação OpenAPI.
14. Ambiente sobe por Docker Compose sem perder dados ao recriar containers.
15. Projeto possui testes automatizados básicos para autenticação, RBAC e segregação.
