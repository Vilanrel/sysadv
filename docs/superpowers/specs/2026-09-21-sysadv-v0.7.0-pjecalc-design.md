# SysADV v0.7.0 — Integração PJe-Calc e Login com Marca d'Água

## 1. Objetivo

Evoluir o SysADV v0.6.0 para suportar o ciclo de preparação, validação, intercâmbio e acompanhamento de cálculos compatíveis com o PJe-Calc, preservando rastreabilidade e operação manual quando não houver automação local disponível. A tela de login também passa a exibir o símbolo da Justiça como marca d'água discreta, sem prejudicar contraste, leitura ou acessibilidade.

## 2. Premissas e limites

- O PJe-Calc permanece uma aplicação externa/local. O SysADV não presume uma API remota pública inexistente.
- O intercâmbio principal será por artefatos de cálculo e arquivos `.PJC`, com suporte a importação/exportação conforme o fluxo documentado no PJe-Calc.
- A automação local será opcional, por agente controlado, separado da API web.
- Sem agente, o cálculo continua operacional em modo manual: gerar pacote, baixar, processar no PJe-Calc e reimportar resultados.
- O SysADV não inventará resultados nem marcará cálculo como concluído sem artefato ou confirmação explícita da execução.

## 3. Arquitetura

Processo SysADV → Calculation Workspace → PJeCalc Mapper → Package Builder → PJeCalcPackage → (download manual OU PJeCalc Agent) → execução local → artefatos/resultados → SysADV → auditoria/versionamento.

Componentes:

1. **Calculation Workspace**: dados contratuais, históricos, verbas, reflexos, jornada, faltas, férias, FGTS, previdência, IR, honorários, custas e índices.
2. **PJeCalc Mapper**: transforma os dados estruturados do SysADV no modelo intermediário necessário ao pacote de intercâmbio.
3. **Package Builder**: gera metadados, manifesto, checksum e artefato `.PJC` quando tecnicamente possível a partir do formato suportado; caso a geração binária dependa de estrutura não documentada, gera pacote de preparação validável e exige importação/exportação pelo agente/local.
4. **PJeCalc Agent**: serviço local opcional que recebe jobs, manipula arquivos e retorna resultados; não expõe credenciais do usuário ao backend.
5. **Artifact Store**: guarda `.PJC`, PDFs, planilhas, relatórios e arquivos de retorno com hash e versão.
6. **Audit Trail**: registra criação, validação, geração, download, envio, processamento, importação, falha e comparação.

## 4. Estados do cálculo

- DRAFT
- DATA_PENDING
- READY_FOR_REVIEW
- VALIDATED
- PJC_GENERATED
- QUEUED
- PROCESSING
- COMPLETED
- COMPLETED_WITH_WARNINGS
- FAILED
- CANCELLED

Transições inválidas devem retornar erro de domínio e não alterar o registro.

## 5. Modelo de dados

### Calculation
Mantém vínculo com organização e processo; adiciona `currentVersionId`, `validatedAt`, `validatedById`, `completedAt`.

### CalculationVersion
Versão imutável dos parâmetros consolidados: `version`, `status`, `snapshot`, `createdById`, `createdAt`.

### CalculationParameter
Parâmetros de cabeçalho do cálculo: datas, regime, índices, opções globais e metadados.

### CalculationSalaryHistory
Competência, salário, base e observação.

### CalculationEarning
Verba, tipo, base, quantidade, divisor, percentual, período, incidências e expressão de cálculo quando aplicável.

### CalculationReflection
Origem, destino, regra e incidências.

### CalculationWorkSchedule
Jornada, escalas, intervalos e parâmetros de horas extras.

### CalculationAbsence / CalculationVacation
Períodos e efeitos no cálculo.

### CalculationFgts / CalculationSocialSecurity / CalculationIncomeTax / CalculationFee / CalculationCost
Parâmetros próprios por bloco.

### PjeCalcPackage
`id`, `calculationId`, `versionId`, `status`, `mode`, `fileName`, `mimeType`, `sizeBytes`, `sha256`, `storagePath`, `manifest`, `createdAt`.

### PjeCalcExecution
`id`, `calculationId`, `packageId`, `agentId`, `status`, `startedAt`, `finishedAt`, `errorCode`, `sanitizedError`.

### PjeCalcArtifact
`executionId`, `type` (`PJC`, `PDF`, `XLSX`, `JSON`, `LOG`), `fileName`, `sha256`, `storagePath`, `createdAt`.

### PjeCalcAgent
`organizationId`, `name`, `machineId`, `version`, `status`, `lastHeartbeatAt`, `capabilities`, `createdAt`.

## 7. Interface do usuário

O menu Cálculos passa a abrir um workspace com abas:

- Resumo
- Contrato
- Histórico Salarial
- Verbas
- Reflexos
- Jornada
- Faltas
- Férias
- FGTS
- Previdência
- Imposto de Renda
- Honorários
- Custas
- Índices / Correção
- Resultado
- PJe-Calc

A aba PJe-Calc deve oferecer:

- Validar parâmetros
- Gerar pacote
- Baixar `.PJC`/pacote disponível
- Enviar ao agente local quando houver agente ativo
- Acompanhar execução
- Importar resultado manual
- Baixar artefatos de retorno
- Comparar versões

## 8. Agente local

- Autenticação por token específico do agente, armazenado de forma segura.
- Heartbeat periódico.
- Pull de jobs, nunca acesso direto do backend ao desktop do usuário.
- Um job pertence a uma organização e cálculo específicos.
- O agente só recebe os arquivos/metadados necessários ao job.
- O agente deve retornar checksum e metadados dos artefatos.
- Falha no agente não elimina o pacote nem impede o modo manual.

## 9. Segurança e auditoria

Auditar pelo menos:

- CALCULATION_CREATED
- CALCULATION_VERSION_CREATED
- CALCULATION_VALIDATED
- PJECALC_PACKAGE_GENERATED
- PJECALC_PACKAGE_DOWNLOADED
- PJECALC_EXECUTION_QUEUED
- PJECALC_EXECUTION_STARTED
- PJECALC_EXECUTION_COMPLETED
- PJECALC_EXECUTION_FAILED
- PJECALC_RESULT_IMPORTED
- PJECALC_ARTIFACT_DOWNLOADED
- CALCULATION_COMPARED

Arquivos e artefatos devem possuir SHA-256. Segredos, tokens e credenciais nunca entram em logs ou auditoria.

## 10. Login — símbolo da Justiça como marca d'água

A tela de login mantém a divisão atual em painel institucional e painel de autenticação. O painel institucional receberá uma marca d'água vetorial inspirada no símbolo da Justiça (balança), com estas regras:

- elemento decorativo, sem função de conteúdo;
- `aria-hidden="true"`;
- opacidade baixa (aprox. 6% a 10%);
- posicionamento absoluto, centralizado/diagonal no painel esquerdo;
- escala responsiva sem cobrir título, texto ou controles;
- não usar imagem externa nem dependência de CDN;
- usar SVG inline ou CSS mask para preservar nitidez;
- manter contraste WCAG dos textos e botões;
- não aparecer no painel de formulário em telas menores quando o painel institucional já é ocultado.

## 11. Testes de aceite

1. Criar cálculo ligado a processo e abrir workspace.
2. Salvar parâmetros por domínio e criar nova versão imutável.
3. Bloquear validação quando existirem campos obrigatórios pendentes.
4. Validar cálculo e registrar usuário/data.
5. Gerar pacote e checksum.
6. Permitir download manual do pacote/artefato.
7. Criar execução somente a partir de cálculo validado e pacote existente.
8. Operar sem agente instalado pelo fluxo manual.
9. Importar artefato de resultado e concluir cálculo somente após validação do retorno.
10. Comparar duas versões e exibir diferenças estruturadas.
11. Auditar todas as ações críticas.
12. Exibir marca d'água da Justiça no login sem interferir no formulário.
13. Frontend, API e scripts reportam `0.7.0`.
14. Atualização por `prisma db push` não remove dados da v0.6.0.

## 12. Critério de conclusão da release

A v0.7.0 só será considerada pronta quando API e frontend compilarem, testes automatizados dos novos fluxos passarem, schema Prisma gerar sem erro, verificador de release confirmar as capacidades novas e o pacote não contiver `.env`, segredos ou API keys.
