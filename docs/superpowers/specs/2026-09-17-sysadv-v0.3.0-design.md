# SysADV v0.3.0 — Design de Integrações, Manutenção e Menus

## Objetivo
Evoluir o SysADV v0.2.1 para uma versão operacional com acompanhamento do consumo DataJud, manutenção completa de processos, consulta DataJud forçada e menus funcionais para Auditoria, Administração, Dashboard e Cálculos iniciais.

## Escopo aprovado

### Consumo da API
Criar `IntegrationRequest` para registrar chamadas DataJud por organização, usuário e processo/NPU, incluindo TRT, endpoint, método, HTTP status, sucesso/erro, duração, finalidade e timestamp. Nunca persistir APIKey, tokens ou segredos.

Criar endpoints de resumo e listagem paginada e uma página `Integrações > Consumo da API` com indicadores de hoje/mês, sucessos, falhas e latência média.

### Manutenção de processos
Adicionar exclusão lógica em `LegalProcess` com `deletedAt`, `deletedById` e `deletionReason`. Listagens comuns ignoram excluídos. Administrador pode listar excluídos e restaurar. Alterações e exclusões devem gerar `AuditEvent`.

A UI deve oferecer Visualizar, Alterar, Excluir, Restaurar (admin) e Consultar DataJud agora.

### Consumo DataJud forçado
A rota já existente de refresh será promovida a fluxo explícito de consulta forçada. Toda execução cria `IntegrationRequest`, mesmo em falha. Campos com evidência VALIDATED nunca são sobrescritos; quando o valor oficial divergir, registrar evidência DIVERGENCE. A resposta deve informar campos alterados, preservados e divergentes.

### Menus funcionais
- Dashboard: indicadores reais de processos, documentos, usuários e integrações.
- Processos: CRUD lógico + consulta forçada.
- Documentos: listagem global e navegação para processo/download quando permitido.
- Cálculos: ciclo inicial persistente vinculado ao processo, com status DRAFT/READY/PROCESSING/COMPLETED/FAILED e parâmetros JSON; não simular execução PJe-Calc.
- Auditoria: consulta paginada de `AuditEvent` com filtros por ação, processo e período.
- Administração: gestão de usuários já existente, mantendo controle por permissão.
- Integrações: consumo DataJud e status de configuração.

## Segurança e autorização
Preservar RBAC atual. Exclusão/restauração exige `process.update`; consulta de consumo exige `audit.read`; cálculos usam `process.read` para leitura e `process.update` para mutações. Não logar `DATAJUD_API_KEY` nem headers sensíveis.

## Modelo de dados
Adicionar `IntegrationRequest` relacionado opcionalmente a `LegalProcess` e `User`. Adicionar campos de soft delete em `LegalProcess`. Adicionar `Calculation` com `organizationId`, `processId`, status, params JSON, timestamps e auditoria indireta via `AuditEvent`.

## Fluxos
1. Consulta automática ou forçada chama `ProcessIntegrationService`.
2. Cliente DataJud mede duração e retorna resposta normalizada + metadados HTTP.
3. Serviço grava `IntegrationRequest` em sucesso ou falha.
4. Fluxo de refresh reconcilia os campos com validações existentes.
5. UI apresenta resultado e histórico de consumo sem revelar segredos.

## Testes
